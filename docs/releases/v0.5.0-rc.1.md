# AI Engineering Framework v0.5.0-rc.1

## Estado de publicación

Esta es la primera release candidate preparada localmente. Hasta que exista
autorización explícita, no crear `v0.5.0-rc.1`, no hacer push y no publicar una
GitHub Release. La versión aplica solo a `ai-engineering-framework`; los
laboratorios Java y Angular no pertenecen al ciclo de publicación.

## Capacidades incluidas

- MVP: instrucciones, agente de orquestación y gobierno Java.
- M1: OpenAPI/DDD y Liquibase XML.
- M2: contratos de requerimientos/HTML/YAML y flujo M2 fail-closed.
- M3: Gatling, perfiles locales, vistas 4+1 y ADR.
- M3.1: Cypress y evidencia funcional local; Playwright permanece disponible.
- M3.3: revisión de seguridad, reportes Markdown/JSON y `security-findings/v1`.
- M4: instalador, locks, bootstrap, políticas aisladas y propuestas locales de
  actualización.
- M5: `universal-governance`, perfiles Java/Angular/React/FastAPI y fixtures
  técnicos React/FastAPI.

## Instalación y bootstrap

```bash
python3 tools/install.py --target ../consumer --profile react --dry-run

python3 tools/bootstrap.py \
  --target ../consumer \
  --version 0.5.0-rc.1 \
  --client-policy path/to/client-policy.json \
  --profile python-fastapi \
  --dry-run
```

El lock registra versión, commit de origen, capacidades y hashes. Las políticas
del cliente se guardan aisladas dentro de cada consumidor y no pueden desactivar
controles obligatorios. Las migraciones desde `java-base` requieren
`--migrate-stack` y revisión del plan generado por dry-run.

## Requisitos y compatibilidad

- Repositorio Git destino y fuente local limpia.
- Herramientas del stack elegido instaladas por el consumidor: Java/Maven,
  Node/npm, o Python/uv según corresponda.
- Compatibilidad verificable de upgrade desde locks `v0.2.0`, `v0.3.0` y
  `capability-lock/v1`.
- Los laboratorios son evidencia técnica y no se versionan/publican junto al
  framework.

## Evidencia de validación

La preparación RC ejecuta regresión de framework, instalador, bootstrap,
perfiles y validación de integridad. Las capacidades funcionales, rendimiento y
seguridad fueron demostradas en laboratorios locales autorizados. Consultar
`docs/release-readiness.md` y los reportes M2–M5 para alcance y límites.

## Limitaciones conocidas

- No hay fuente/versionado remoto firmado, release publicada ni artefacto
  descargable verificable.
- La automatización remota de Pull Requests no se ejecutó.
- SSH/PREPARE/VERIFY es fail-closed, pero no hay evidencia formal para un
  consumidor real ejecutado.
- Las pruebas de navegador, rendimiento y seguridad no certifican producción.

## Actualización recomendada

1. Trabajar desde un checkout limpio y respaldar el lock del consumidor.
2. Ejecutar `bootstrap.py` o `install.py` con `--dry-run`.
3. Revisar capacidades, hashes, política y cualquier migración de stack.
4. Aplicar la actualización solo tras aprobación humana.
5. Ejecutar build, pruebas y controles propios del consumidor antes de merge.
