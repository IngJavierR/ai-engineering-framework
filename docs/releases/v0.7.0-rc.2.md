# AI Engineering Framework v0.7.0-rc.2

## Estado de publicación

Release candidate preparada localmente. Hasta que exista autorización explícita,
no crear el tag `v0.7.0-rc.2`, no hacer push y no publicar una GitHub Release.

## Correcciones incluidas

- El scaffold backend usa el consumidor indicado y crea el changelog maestro
  de Liquibase cuando falta.
- Las rutas de changelog y Gatling se resuelven desde el consumidor, salvo que
  se indique explícitamente `--workspace-root`.
- `validate_backend_contracts.py` separa `preflight`, que admite un changelog
  aún no creado, de `verify`, que requiere un changelog XML válido.
- El workflow backend PREPARE/VERIFY reutiliza el guard de alcance Git de M2 y
  exige que los cambios observables estén dentro de `scope`.
- La guía Liquibase documenta PostgreSQL para stacks no JVM mediante Docker,
  Liquibase 5.x y `lpm add postgresql`.

## Evidencia de validación

- Pruebas focalizadas: `21 passed, 7 subtests passed`.
- Flujo temporal backend: `new_feature.py` y `refresh_manifest.py` finalizaron
  en `VALID` sin usar `--workspace-root`.
- La suite completa ejecutó `136 passed, 129 subtests passed`; siete pruebas de
  bootstrap/perfiles quedaron bloqueadas por la política existente que exige
  fuente Git limpia durante la ejecución del instalador.

## Compatibilidad y límites

- El cambio es compatible para consumidores: `--workspace-root` conserva su
  función como override explícito.
- La validación completa tras commit y con el árbol fuente limpio sigue siendo
  requisito previo para publicación.
